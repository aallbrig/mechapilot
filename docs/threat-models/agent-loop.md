# Threat model: Agent Loop

Covers the Supervisor (`scripts/agent-loop-supervisor`), the sandboxed session and its settings (`.claude/agent-loop-settings.json`), the skill (`.claude/skills/agent-loop/SKILL.md`) and the wrappers it calls. The attacker is the unattended session itself, possibly prompt-injected through a public issue, trying to act outside its sandbox or its allowlist.

| ID | Attack class | Description | Found | Status | Mitigation | Proof |
| --- | --- | --- | --- | --- | --- | --- |
| AL-01 | Session-editable code runs outside the sandbox | Hooks and the status line ran scripts from the session's own checkout, with the user's full access. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | Hooks, the status line and the skill come from a read-only export of a commit a human pinned. | `test:test_supervisor_exports_only_the_pinned_runtime` |
| AL-02 | Allow rule runs arbitrary commands | `mise exec`, `git rebase --exec`, `--upload-pack`, `find -exec` and attached `gh api -X` forms slipped past the deny list. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | The OS sandbox is the boundary; dangerous forms are denied and nothing allowed pushes, calls the API or runs mise. | `test:test_agent_loop_settings_sandbox_the_session` |
| AL-03 | Refspec smuggling | An allowed push rule matched a `branch:refs/tags/v1` refspec and `+` force refspecs. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | Pushes go only through `scripts/agent-loop-push`, which builds a fixed refspec. | `test:test_agent_loop_push_pushes_only_its_branch` |
| AL-04 | Skill command outside the allowlist | The skill told the session to run commands the allowlist denies, so the loop stalled or filed false requests. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | Every backticked skill command is matched against the allow and deny rules. | `check:agent-loop-skill-commands` |
| AL-05 | Tool that ignores the sandbox proxy | A check that connects directly, not through the proxy, always failed inside the sandbox and would file a false incident. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | Production is checked by the Supervisor outside the sandbox; the skill only reads its result. | `check:agent-loop-skill` |
| AL-06 | Auto-follow of main | The runtime followed `origin/main`, so a change the session merged ran unsandboxed at the next start. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | The runtime is exported only from the human-pinned commit. | `test:test_supervisor_exports_only_the_pinned_runtime` |
| AL-07 | Write through a planted symlink | The unsandboxed Supervisor wrote a marker through a link the session planted in its checkout. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | After clone creation the Supervisor never writes into the checkout. | `test:test_supervisor_never_writes_into_the_checkout` |
| AL-08 | TOCTOU parent-directory swap | A checked parent component was swapped for a link between the check and an unsandboxed `mv`. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | Deps are built read-only in the state dir and copied in by the sandboxed session. | `test:test_supervisor_ignores_links_swapped_in_during_a_tick` |
| AL-09 | Localhost binding | `allowLocalBinding` opened every localhost port (IDE bridges, the Godot editor) and listened on all interfaces. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | Local binding stays off; Chrome and Lighthouse steps run only in the `ci` check. | `test:test_agent_loop_settings_sandbox_the_session` |
| AL-10 | Unpinned hooks at clone creation | Creating the clone checked out `origin/main` with hooks on, running its `post-checkout` outside the sandbox. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | The Supervisor runs every git call with hooks and fsmonitor off. | `test:test_supervisor_runs_no_git_hooks` |
| AL-11 | Stale pid kill | A recorded pid reused after a reboot could get an unrelated process tree killed. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | Only a pid whose start time and command match the record is killed. | `test:test_supervisor_kills_only_the_recorded_session_process` |
| AL-12 | Leftover sandboxed process | A background process from a previous session survives into the next tick. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | The Supervisor refuses to start while any process uses the checkout (defence in depth). | `test:test_supervisor_refuses_while_processes_use_the_checkout` |
| AL-13 | Escalation on nudges that worked | Nudges followed by activity still counted, filing false stall issues. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | Only nudges after the last sign of life count. | `test:test_supervisor_files_a_stall_issue_after_failed_nudges` |
| AL-14 | Hostname in a public issue | A machine identity derived from the hostname would reach issues and labels. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | The machine alias comes from random bytes only. | `test:test_machine_alias_is_not_hostname` |
| AL-15 | Attested token permissions | Preflight cannot probe the token's Workflows, Environments, Variables or Deployments write; a human attests them. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | residual | Accepted: `task loop:confirm-token`, with a fingerprint that forces a new attestation for a new token. | #67 |
| AL-16 | Token readable inside the sandbox | Sandboxed code can read the token from its environment and post it to an allowed host. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | residual | Accepted: least-privilege token, network limited to GitHub and the two sites. | #67 |
| AL-17 | Inherited git config re-enables hooks | An inherited `GIT_CONFIG_PARAMETERS` is read after the Supervisor's own overrides. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | The Supervisor (and the launcher, for the session) unsets `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG`, `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and the other repository-selecting variables before any git call. | `test:test_supervisor_ignores_inherited_git_environment` |
| AL-18 | Hooks-off config leaks into a new tmux server | A tmux server the Supervisor starts kept its hook-free git config for every pane a human opens in it later. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | `do_start` and `loop:start` clear the `GIT_CONFIG_*` and metrics variables for the call that creates a server. | `test:test_supervisor_new_tmux_server_gets_no_hooks_off_config` |
| AL-19 | Same-name session taken for the loop's | A human session named like the loop's could be recorded, prompted or killed. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | Only the pid of the session's own tmux pane counts (the pane runs `exec <launcher>`), `record_session` re-checks it, and nothing is killed by name. | `test:test_supervisor_matches_the_session_by_pane_pid_only` |
| AL-20 | Pinned hooks run checkout code first | The pinned hooks sourced the checkout's `scripts/lib-toolchain` and ran mise on its untrusted `.mise.toml`. | [#62](https://github.com/aallbrig/mechapilot/pull/62) | mitigated | Hooks source the pinned copy beside them; in the session they run no mise. | `test:test_pinned_hooks_use_the_pinned_toolchain` |
| AL-21 | Hook runs outside the sandbox unnoticed | A harness git call with the session's environment could run the pinned hooks unsandboxed. | [#70](https://github.com/aallbrig/mechapilot/pull/70) | mitigated | Detection: such a hook can write the state dir and leaves `hook-outside-sandbox`, which fails preflight; the first-run checklist checks it by hand. | `test:test_preflight_fails_after_a_hook_ran_outside_the_sandbox` |
| AL-22 | Production job through a remote reusable workflow | A push-triggered job calling another repository's workflow got its `environment: production` in this repository. | [#70](https://github.com/aallbrig/mechapilot/pull/70) | mitigated | `production-dispatch-only` rejects job-level `uses` outside `./` in any workflow that isn't dispatch-only, normalises environment names and permissions, and refuses duplicate trigger keys. | `test:test_production_jobs_run_only_on_dispatch` |
| AL-23 | Outsider text steers triage | Anyone can open or comment on a public issue, and triage turns its text into acceptance criteria the loop implements. | [#70](https://github.com/aallbrig/mechapilot/pull/70) | mitigated | Triage reads issues only through `scripts/agent-loop-gh triage-view`, which passes only OWNER, MEMBER and COLLABORATOR text; an outsider's issue goes to the owner. | `test:test_agent_loop_skill_triages_needs_triage_issues` |
