# Threat model: asset credits

Covers `scripts/checks/asset-credits` and `godot/CREDITS.md` (#27). The attacker is a change that ships a third-party image, sound, font, model or texture in the game without a credit row naming its source and licence, while `check:asset-credits` still passes.

| ID | Attack class | Description | Found | Status | Mitigation | Proof |
| --- | --- | --- | --- | --- | --- | --- |
| AC-01 | Folder credit covers later files | An original-work row credited whole folders, so a third-party file added to one later passed with no row of its own. | [#91](https://github.com/aallbrig/mechapilot/pull/91) | mitigated | Only third-party rows may credit a directory; original work is credited file by file, or with no path when it ships no asset file. | `test:test_asset_credits_rejects_a_new_asset_under_an_original_work_directory` |
| AC-02 | Unlisted media extension | Fonts and video Godot imports (`.ttc`, `.otc`, `.pfb`, `.pfm`, `.font`, `.ogv`) were not treated as assets. | [#91](https://github.com/aallbrig/mechapilot/pull/91) | mitigated | Every extension the pinned Godot can import or load is an asset, except a short list of text formats; the test asks Godot for its list. | `test:test_asset_credits_covers_every_importable_extension` |
| AC-03 | Media embedded as an unlisted class | An SVG embedded as a `DPITexture` in a `.tres` or `.tscn` passed, because only some media classes were recognised inside text resources. | [#91](https://github.com/aallbrig/mechapilot/pull/91) | mitigated | Every Godot subclass of Texture, AudioStream, Font, Mesh and Image is classified as media or procedural; a new class fails the test until classified. | `test:test_asset_credits_classifies_every_media_class` |
| AC-04 | Formatting hides a tag | Text matching missed embedded media written with spaces around `=`, an indented or line-split header, or `PackedByteArray (`, all of which Godot loads. | [#91](https://github.com/aallbrig/mechapilot/pull/91) | mitigated | Text resources and scenes fail closed: a scan that reads tags the way Godot's parser does lists every declared resource class, and the file is an asset unless all of them are allowlisted and it holds no PackedByteArray; anything the scan cannot follow is an asset. | `test:test_asset_credits_rejects_embedded_media_in_any_formatting_godot_parses` |
| AC-05 | Inline object value | An inline `Object(DPITexture,...)` property value built a texture in place, in a `.tres` declared as a plain material and on a `.tscn` node line, and Godot loaded it. | [#91](https://github.com/aallbrig/mechapilot/pull/91) | mitigated | Any `Object(` outside a string makes a text resource or scene an asset (Godot never writes one when saving), and scene node classes are allowlisted, failing closed on any other. | `test:test_asset_credits_rejects_embedded_media_in_any_formatting_godot_parses` |
| AC-06 | Control bytes and duplicate keys | Godot reads any byte up to 0x20 as whitespace, so a vertical tab or form feed hid a `type` or an `Object(` from the scan, and of two `type` keys in a header Godot uses the last. | [#91](https://github.com/aallbrig/mechapilot/pull/91) | mitigated | A control byte other than tab, LF and CR is an error; a tag must start a line with single-space separators; a duplicate `type` makes the file an asset. | `test:test_asset_credits_rejects_embedded_media_in_any_formatting_godot_parses` |
| AC-07 | Hand-written text resource | Text resources can be written in endless forms Godot still loads, so a pattern scan could always be outrun by another spelling. | [#91](https://github.com/aallbrig/mechapilot/pull/91) | mitigated | Every committed .tres, .tscn and .escn must be byte-for-byte what the pinned Godot writes when it re-saves the file (`check:godot-canonical`, in the sandbox); the scan then reads only Godot's own form. | `test:test_godot_canonical_rejects_every_hand_written_media_variant` |
